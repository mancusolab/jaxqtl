Paths are repository-relative to `/Users/nicholas/Projects/jaxqtl` and are exact unless identified as generated evidence directories.

## Test-design rules

1. Test observable behavior through public or phase-owned boundaries. Dense matrices are permitted only as small independent test oracles.
2. Use real temporary SciPy, Polars, Parquet, Arrow, NPZ, filesystem, wheel, and sdist boundaries where feasible; do not assert internal mock call sequences.
3. Use bounded Hypothesis tests for normalization, serialization, deterministic ordering, and block-equivalence properties. Keep explicit examples for empty, singleton, repeated-spectrum, corruption, rank, and numerical-failure cases.
4. Exercise eager/JIT agreement, fixed PyTree shapes, supported JVPs, solver statuses, nonfinite handling, and fixed-shape block invariance. Do not infer transform correctness from primal output alone where the phase requires AD coverage.
5. Run x64 configuration tests in isolated subprocesses. Public numerical boundaries must reject bool/complex leaves, promote accepted real inputs to float64, require enabled x64, and verify an actual float64 probe on the resolved backend before tracing, drawing, fixture generation, or artifact staging.
6. Reconcile tabular inputs by explicit keys, validate cardinality/null/missing/duplicate policies, freeze deterministic order, and materialize once before array conversion. Polars objects do not enter JAX kernels.
7. Full calibration and OneK1K runs are automated non-CI system evidence, not manual substitutes. Evidence must be generated from the pinned clean source/config state, published atomically to a previously nonexistent versioned path, and validated by the planned tests.
